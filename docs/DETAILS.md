# Photosorter

Локальная сортировка домашнего фото/видео-архива по людям и сюжетам: находит все лица, группирует их
по людям без эталонных фото, классифицирует сцены, ищет по тексту и даёт удобно чистить архив
(удаление обратимо). Всё работает локально, без облака.

Архив: `\\nas\home\Photos` (NAS). Из архива скрипты только **читают**; меняет файлы только удаление,
сделанное пользователем в интерфейсе (файлы уходят в карантин, см. «Удаление»).

## Быстрый старт

```powershell
cd C:\path\to\photosorter
.venv\Scripts\streamlit run app.py          # интерфейс: http://localhost:8501
```

Новые файлы в архиве — пересканировать (инкрементально, только новые/изменённые):

```powershell
.venv\Scripts\python photosorter.py scan --src "\\nas\home\Photos"
.venv\Scripts\python photosorter.py cluster
.venv\Scripts\python scenes.py embed
.venv\Scripts\python scenes.py tag
.venv\Scripts\python stacks.py build      # стопки похожих (секунды)
.venv\Scripts\python stacks.py score      # оценка качества в стопках (~5 мин, читает оригиналы)
```

Полный первый проход по архиву (~19 тыс. файлов, 650 ГБ) занял ~50 минут.

## Установка с нуля

Python 3.11, Windows, NVIDIA GPU (проверено на RTX 5070 Ti; без GPU работает на CPU, медленнее).

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

Модели (в `models/`, в репозиторий не кладутся — большие):

| Файл | Откуда | Зачем |
|---|---|---|
| `models/det_10g.onnx`, `models/w600k_r50.onnx` | `buffalo_l.zip` из релиза InsightFace v0.7 (github.com/deepinsight/insightface/releases) | детектор лиц SCRFD + распознавание ArcFace |
| `models/siglip2/**` | huggingface.co/immich-app/ViT-B-16-SigLIP2__webli (`config.json`, `visual/*`, `textual/*`) | классификация сцен и поиск по тексту (понимает русский) |

Лицензия весов InsightFace — только некоммерческое использование (для личного архива ок).

### Особенности окружения

- Вывод кириллицы в bash-конвейере: `PYTHONIOENCODING=utf-8`.
- Интерфейс слушает **только localhost** (`.streamlit/config.toml`) — в сеть фото не уходят.

## Из чего состоит

| Файл | Что делает |
|---|---|
| `photosorter.py` | Ядро и CLI: сканирование (лица, метаданные, превью), кластеризация, БД, удаление/восстановление |
| `scenes.py` | SigLIP2: векторы превью, категории сцен (zero-shot), поиск по тексту |
| `stacks.py` | Стопки похожих фото (серии, дубли с разных устройств, копии) и оценка качества внутри стопки |
| `app.py` | Интерфейс на Streamlit (многостраничный, у каждого раздела свой URL) |
| `grid.py` | Своя сетка карточек (Streamlit components v2, JS): выделение как в проводнике, полноэкранный просмотр, Ctrl+D/Ctrl+Z |
| `media_server.py` | Мини HTTP-сервер на 127.0.0.1 со случайным токеном: отдаёт оригиналы в просмотрщик (HEIC/RAW → JPEG, видео с Range) |
| `protected.txt` | Папки, из которых удалять нельзя вообще (сейчас пусто — защита снята по решению пользователя) |
| `tools/` | Проверка качества кластеризации на датасете LFW |
| `faces.db` | SQLite с результатами (не удалять: в ней имена людей, журнал удалений для отмены) |

### Конвейер

1. **scan** — для каждого файла: декодирование (OpenCV; HEIC через pillow-heif; RAW `.cr3` — встроенное JPEG-превью через rawpy;
   видео через PyAV — переход по ключевым кадрам раз в 2 с, с учётом поворота у телефонных видео) →
   детектор SCRFD в двух масштабах (960 и 480 px: второй нужен для лиц на весь кадр — селфи) →
   выравнивание по 5 точкам → ArcFace-вектор 512 → миниатюра лица. Плюс EXIF (дата, GPS, камера),
   метаданные видео, dHash (дубли), превью 320 px (1 на фото, до 6 на видео). Файлы обрабатываются в 8 потоков.
   Офлайн-геокодинг координат → «Город, регион, страна» (reverse_geocoder).
2. **cluster** — только качественные лица (≥40 px, score ≥0.65) → kNN-граф (косинус) → Chinese Whispers →
   слияние кластеров с близкими центроидами → остальные лица прикрепляются к ближайшему человеку →
   выкидываются «люди» из одного файла. Номера и имена людей сохраняются между пересчётами
   (по большинству старых привязок лиц и по центроидам названных людей).
3. **scenes embed/tag** — SigLIP2 по превью из БД (оригиналы не нужны), категории — softmax по
   описаниям из `CATEGORIES` в `scenes.py` (у файлов без лиц «людские» категории исключены, «Прочее» — запасная).
4. **recheck** — находит по превью файлы, где на превью видно крупное лицо, которого нет в БД, и помечает их
   на пересканирование (пригодилось, когда детектор пропускал селфи).

### База (`faces.db`)

- `files` — файл, тип, размеры, длительность, `n_faces` (0 = без людей), `taken_at` + `date_source`, GPS, `place`, камера, `phash`
- `faces` — лицо: файл, `person_id` (NULL = не сгруппировано), бокс, время в видео, вектор (float16), миниатюра,
  `manual` (1 = человек указан вручную; `cluster` такие лица не трогает)
- `persons` — человек: имя, скрыт ли, счётчики, центроид
- `previews` — JPEG-превью; `clip` — векторы SigLIP2; `tags` — топ-3 категории
- `deleted` — журнал удалений: куда ушёл файл и **снимок всех его строк** (для Ctrl+Z / `restore`)
- `not_same` — пары людей, помеченные «это разные люди»
- Представления: `file_people` (кто на каждом файле), `person_files`, `files_without_people`,
  `files_strangers_only`, `duplicates`

Пример: все фото, где Петя ровно вдвоём с кем-то:

```sql
SELECT path, people FROM file_people WHERE people LIKE '%Петя%' AND n_people = 2;
```

## Интерфейс

Разделы (меню слева, у каждого свой адрес; фильтры тоже в адресе — работают F5, «назад/вперёд», закладки;
позиция прокрутки запоминается для каждого экрана):

- **Люди** `/people` — карточки кластеров: имя прямо на карточке, «Объединить», «Скрыть»,
  «Файлы только с выбранными». **Человек** `/person?id=N` — его файлы с режимами
  «только он(а) в кадре» (ни одного другого лица) / «без других знакомых» / «с другими» и фильтром «С кем в кадре».
- **Только выбранные люди** `/only?ids=1,2` — файлы, где в кадре только выбранные люди.
- **Похожие люди** `/similar` — пары кластеров с похожими центроидами (кандидаты на объединение).
- **Подборки** `/collections` — см. ниже.
- **Поиск** `/search?q=...`, **Все файлы**, **Без людей**, **Только посторонние**, **Видео** — с фильтрами
  год / категория / место. Видео по умолчанию скрыты из списков (переключатель «Показывать и видео»);
  пока они скрыты, на странице «Люди» считаются только фото и не видны люди, которые есть только в видео.

Сетка файлов: клик / Ctrl+клик / Shift+клик / рамка мышью / Ctrl+A / Esc; Delete или 🗑 — удалить сразу, без вопросов;
«Удалить все, кроме выбранных»; двойной клик / Enter / ⤢ — полноэкранный просмотр оригинала
(← →, F — полный экран, Delete или Ctrl+D — удалить сразу, **Ctrl+Z — вернуть**).

Переключатель «Скрывать то, что в подборках» (слева, включён по умолчанию) убирает из всех сеток файлы,
которые уже лежат в подборках (кроме страницы «Подборки»).

**«👤 Кто на фото»** (в сетке и «👤 Кто это» в просмотре) — исправить ошибки распознавания вручную:
диалог показывает все лица с выделенных файлов (в видео — одно лицо на человека), у каждого свой выбор
«кто это» (подписанные люди, люди с этих файлов, «никто из знакомых»), можно сразу создать нового человека.
«Быстро: поставить всем сразу» меняет лица разом; на странице человека можно выбрать «Кому»: только его лицам
или всем лицам на выбранных фото. Быстрый выбор действует и на лица, не поместившиеся в окно (показывается 60).
На групповых фото каждое лицо правится отдельно. Кнопка есть во всех сетках, включая «Подборки».
На странице человека «🔗 Это на самом деле другой человек…» переносит все его лица к выбранному
(или новому) человеку и открывает его страницу; Ctrl+Z отменяет. Изменения ставят `faces.manual = 1`, «Пересчитать кластеры» их сохраняет;
Ctrl+Z отменяет. «Это не он(а)» на странице человека работает так же (отвязывает и запоминает).
Функции: `file_faces`, `assign_faces`, `unassign_faces`, `create_person`.

## Подборки (отправить людям и удалить)

Сценарий: собрать → упаковать → отправить → удалить.

1. В боковой панели выбрать подборку «📥 Подборка» (или создать «➕»). Кнопка «📥 В «…»» в любой сетке
   (и в полноэкранном просмотре) **перемещает** выделенные файлы из архива в папку подборки на этом компьютере
   (по умолчанию `%USERPROFILE%\Pictures\Photosorter\<название>`, меняется на странице «Подборки»).
   Данные в БД едут вместе с файлом (`files.path` обновляется), в подписи карточки — «📥 название».
   Ctrl+Z возвращает файлы на прежнее место.
   **«📥 В подборку…»** (в просмотре «📥 Куда…») — выбрать, куда именно: кнопки подписанных людей на выделенных
   фото (в подборку человека), любая существующая подборка или новая. Выбранная становится текущей.
   В подписи каждой карточки — кто на фото: «👤 Петя, Вася, +2» (+N — неподписанные/незнакомые лица).
   **«👥 По людям»** (в сетке и в просмотре) — каждый файл сам раскладывается по подборкам всех *подписанных*
   людей на нём (подборка человека создаётся при первом использовании, `collections.person_id`).
   Люди с флагом «Не раскладывать по подборкам (это я)» (`persons.skip_collect`) пропускаются.
   **Перемещать / Копировать** (переключатель под подборкой слева, и такой же в окне «📥 В подборку…»):
   «Копировать» кладёт в подборку копию (жёсткую ссылку, если тот же диск), оригинал остаётся в архиве.
   Ctrl+Z, «↩ Убрать из подборки» и «✅ Отправлено — удалить» убирают только копию, архив не трогают.
   Копировать можно и из папок в `protected.txt`. Проверка: `python tools/test_collections.py`.
2. Один файл может быть в нескольких подборках: в первую он **переезжает** с NAS, в остальные кладётся
   **жёсткая ссылка NTFS** (тот же файл, без лишнего места; если ссылка невозможна — копия).
   Раздел **Подборки** `/collections`: содержимое, «↩ Убрать из подборки» (если файл ещё в других подборках —
   уходит только эта ссылка; если это была последняя — файл возвращается в архив на прежнее место),
   «📂 Папка», «📦 ZIP» (`<папка>.zip` рядом, без сжатия — фото/видео уже сжаты; папка открывается в проводнике).
3. «✅ Отправлено — удалить»: файлы, которые есть и в других подборках, там остаются (удаляется только ссылка
   этой подборки); остальные — в Корзину Windows (со снимком строк БД в журнале `deleted`). ZIP — тоже в Корзину.
   Обычное удаление файла (Delete) убирает его из всех подборок сразу.

Таблицы: `collections`, `collection_files` (`link_path` — файл в папке подборки, `original_path` — откуда он
пришёл), `settings` (`collections_root`). Функции в `photosorter.py`: `create_collection`, `add_to_collection`,
`move_to_collection`, `collect_by_people`, `remove_from_collection`, `return_from_collection` (Ctrl+Z),
`zip_collection`, `finish_collection`.

## Стопки похожих (`/stacks`)

Чтобы удалить неудачные дубли: серии, повторные снимки одного момента (в т.ч. с разных телефонов и
фотоаппарата), копии одного кадра (пересланные, уменьшенные, `X(0).jpg`).

- **Группировка** (`stacks.build`): похожесть — нейросеть SigLIP2 (векторы из `scenes.py embed`), время —
  подсказка: чем больше пауза между кадрами, тем выше нужная похожесть (`TIME_THRESHOLDS`: до 2 с — 0.85,
  … до 2 ч — 0.95, окно широкое из‑за разных часов у устройств). Кадр входит в стопку, только если похож и на её
  первый кадр (`ANCHOR_SIM`) — длинная серия делится на моменты. Почти одинаковые картинки (`COPY_SIM` + dHash)
  объединяются в любое время. Скриншоты, документы и чеки — только как точные копии (у каждого свой текст).
- **Оценка** (`stacks.score`, таблица `quality`): по оригиналу (только чтение) — резкость самых резких мест кадра
  (размытый фон не штрафуется), резкость лиц, пере/недоэкспозиция; плюс «красота» по SigLIP2 (подсказки
  «хорошее фото» минус «размытое / закрытые глаза / случайный кадр»). Внутри стопки признаки сравниваются
  между собой (`rank_stack`): ⭐ лучший — 100, худший — 0. Для копий одного кадра важнее разрешение и размер файла.
- **Страница**: стопки по времени, у каждой заголовок; лучший — первым. «⭐ Оставить только лучшие» — во всех
  стопках (или в стопках выделенных фото); «✅ Оставить выбранные» — выделяешь, что нравится, остальное из этих
  стопок удаляется. Удаляется сразу, Ctrl+Z возвращает (и стопку тоже).
  «Собрать стопки заново» / «Оценить качество» — кнопки там же (новые фото после `scan` + `scenes.py embed`).

## Копии (`/copies`)

Один и тот же кадр несколько раз: точные дубли (`X(0).jpg`, бэкап бэкапа), HEIC + его JPEG, RAW + JPEG, уменьшенные
и пересланные копии. Таблица `copies` (строится в `stacks.build`). Пара — копия, если SigLIP2 ≥ 0.985 и dHash ≤ 4,
или dHash ≤ 2 при тех же пропорциях; **не** копия, если у обоих дата из EXIF и она отличается на ≥ 1 с, или
одинаковые разрешение и формат, но разный размер файла (это соседние кадры серии). Группы объединяются, только если
ни одна пара внутри не противоречит этим правилам (нет цепочек «кадр A ~ RAW ~ кадр B»).
Оставляется: наибольшее разрешение → при равном JPEG или оригинал HEIC/RAW (переключатель на странице) → с EXIF →
больший файл → короткое имя. Фильтр «точные дубли» (одинаковые разрешение и размер) — самое безопасное.
«⭐ Оставить по одному во всех группах» / «✅ Оставить выбранные» — сразу, Ctrl+Z возвращает
(если список опустел — кнопка «↩ Вернуть последнее»).

## Удаление и восстановление

- Файлы с NAS не стираются, а перемещаются в `\\nas\home\_photosorter_deleted\<тот же путь>`
  (на сетевых дисках нет Корзины). Локальные файлы — в Корзину Windows.
- Удаление без подтверждения. Ctrl+Z (можно несколько раз подряд, в пределах открытой вкладки) возвращает файлы и их данные в БД по одному действию.
- Из консоли: `photosorter.py restore [--since 2026-10-14T03:10]` — вернуть файлы из карантина
  (удалённые до появления снимков в журнале попадут в БД только после `scan`).
- Окончательно освободить место — вручную удалить папку `_photosorter_deleted`.
- `protected.txt` — папки, удаление из которых заблокировано и в интерфейсе, и в CLI.

## CLI (photosorter.py)

```
scan --src PATH [--det-size 960] [--video-step 2] [--no-video]   сканирование (инкрементальное)
recheck                                                          найти пропущенные лица по превью
cluster [--edge 0.45 --merge 0.55 --assign 0.45 --min-files 2]  группировка по людям
people | name ID "Имя" | merge ID1 ID2 ... | hide ID ...          люди
gallery                                                          статичный people.html (старый вариант просмотра)
export ID [--out _review] / apply                                выгрузить файлы человека на проверку / удалить оставшееся
restore [--since ISO]                                            вернуть удалённое из карантина
```

Общий флаг `--db path` — другая база (так делались все тесты, чтобы не трогать рабочую).

## Как вносить изменения и проверять

- **Интерфейс подхватывает изменения кода на лету** — правки в `app.py`/`grid.py` у открытого интерфейса
  могут дать временную ошибку; после изменений перезапустить `streamlit run` и обновить страницу через Ctrl+F5
  (иначе браузер держит старый JS сетки).
- Изменения кластеризации/детектора проверять на LFW (13 тыс. фото знаменитостей с подписями):
  ```powershell
  # LFW: https://ndownloader.figshare.com/files/5976018 (lfw.tgz) -> распаковать в D:\tmp\lfw
  .venv\Scripts\python tools\make_testset.py D:\tmp\lfw\lfw D:\tmp\testset
  .venv\Scripts\python photosorter.py --db D:\tmp\test.db scan --src D:\tmp\testset
  .venv\Scripts\python photosorter.py --db D:\tmp\test.db cluster
  .venv\Scripts\python tools\evaluate.py D:\tmp\test.db D:\tmp\testset\truth.json
  ```
  Текущий результат: полнота 98.9% (лица человека в его главном кластере), чистота 99.76%.
- UI проверялся в настоящем браузере через Playwright (`pip install playwright`, `playwright install chromium`;
  для H.264-видео — `channel="chrome"`, а для запросов к 127.0.0.1 — `--no-proxy-server` из-за системного прокси).
  Тестовую копию интерфейса запускать на другом порту и с копией базы:
  `streamlit run app.py --server.port 8502 -- --db копия.db`.
- Удалять что-либо в рабочем архиве при тестах нельзя — тестировать удаление только на копиях (LFW).

## Серверная копия (docker)

Эта копия работает на сервере (192.168.1.10) в контейнере `photosorter` (`~/photosorter/docker-compose.yml`).
Код — `~/photosorter/app` (git: первый коммит = Windows-версия), база — `~/photosorter/data/faces.db`,
модели — `app/models` (не в git). Интерфейс: http://192.168.1.10:8501, оригиналы для просмотра: порт 8502 (с токеном).

- Архив NAS смонтирован на хосте в `/mnt/nas-homes` (шара NAS `homes`), в контейнер — тем же путём.
  `PS_PATH_MAP` переводит пути `\nas\home\…` / `\nas\homes\…` в пути монтирования (`ps.map_path`),
  `tools/migrate_paths.py` переписывает пути в копии базы с Windows (или с одной точки монтирования на другую).
- Корзины нет: удалённое уходит в `<корень шары>/_photosorter_deleted/…` (как на Windows), локальные файлы —
  в `data/_photosorter_deleted`. `protected.txt` можно писать Windows-путями — они тоже переводятся.
- Ночью в 3:00 cron пользователя `user` запускает `docker exec photosorter /app/nightly.sh`
  (scan всех `PS_SCAN_SRC` → cluster → scenes embed/tag → stacks build/score), лог `~/photosorter/logs/nightly.log`.
  Папка, которой нет (NAS не смонтирован), пропускается; `scan` на несуществующей папке сразу выходит.
- Обновить код: правка в `~/photosorter/app` → `git commit` → `docker restart photosorter`
  (зависимости поменялись — `docker compose build && docker compose up -d`). CLI: `docker exec -it photosorter python photosorter.py …`.

### Очередь для внешних GPU-воркеров (`queue_api.py`, ps-worker)

Чтобы ночной/ручной скан шёл быстрее, разбор файлов можно отдать видеокарте Windows-ПК (RTX 5070 Ti).
В базу при этом пишет **только сервер**.

- `scan` после обхода папки кладёт новые/изменённые файлы в таблицу `work_queue` и сам разбирает их пачками
  (commit после каждого файла: интерфейс не ловит «database is locked»). Если воркер был на связи в последние
  `PS_QUEUE_LEASE` секунд, `scan` первые `--queue-wait` минут (`PS_QUEUE_WAIT`, по умолчанию 10) оставляет очередь ему,
  потом помогает сам. Воркера нет — всё как раньше, сразу на сервере. Папки нет (NAS не смонтирован) — выход до очереди, ничего не удаляется.
- `queue_api.py` — HTTP API в том же контейнере (запускается из `command` в compose, перезапускается сам при падении),
  порт **8503** (опубликован только на 192.168.1.10). Токен — `data/queue_token` (создаётся при первом запуске)
  или `PS_QUEUE_TOKEN`. Вызовы: `/lease` (пачка с lease на `PS_QUEUE_LEASE`=90 с), `/heartbeat` (продлить, воркер шлёт раз в 30 с),
  `/result` (результат одного файла: метаданные, лица с векторами и миниатюрами, превью, векторы SigLIP2 → `store_file`,
  то же, что пишут `scan` + `scenes.py embed`), `/release` (вернуть незаконченное). Нет heartbeat — пачка через 90 с снова в очереди,
  её доделывает воркер или сам `scan`. Ошибка на воркере — файл помечается `remote_ok=0` и разбирается только на сервере.
- Воркер обязан работать на том же коде: API сравнивает хеш `photosorter.py`+`scenes.py` с диска, при расхождении воркер
  делает `git fetch` из этого репозитория и перезапускается. Поэтому правки кода — коммитить.
- Пустая очередь и воркер ждёт работу → API сам запускает `/app/nightly.sh` (не чаще раза в `PS_QUEUE_AUTOSCAN_MIN`=120 мин,
  0 — никогда; лог `data/nightly-api.log`). Двойной запуск исключён общим `flock` на `/data/nightly.lock`.
- Проверено на копии базы: 241 файл (86 видео) — лиц 1040 у воркера и 1040 у серверного scan, у 1036 из 1038 сопоставленных лиц
  косинус > 0.99 (в двух видео ±1 лицо на границе порога дедупликации), SigLIP2 ≥ 0.9997.
- Тестовый экземпляр (как проверялось): `docker run … -p 192.168.1.10:8504:8503 -v app-dev:/app -v data-test:/data photosorter:local python queue_api.py`
  на копии базы (`con.backup()`), боевую базу не трогает.

Воркер на Windows — отдельный проект ps-worker (не в этом репозитории), запуск ярлыком «PC → server» на рабочем столе
(`photosorter\.venv\Scripts\pythonw.exe worker.pyw`, без консоли; `--start` — сразу начать). Кнопка «Юзай меня полностью» / «Хватит»,
лог (копия в `worker.log`), галочка «Автостоп, когда занята видеокарта»: чужая нагрузка на NVIDIA по счётчикам Windows «GPU Engine»
≥30% два замера подряд — вычисления останавливаются и освобождают видеопамять, <10% три замера (раз в 10 с) — продолжают.
Пока работает — окно поверх всех, жёлтая полоса «⚡ ПК отдаёт мощность серверу».
Вычисления — дочерний `compute.py` в Job Object с KILL_ON_JOB_CLOSE (плюс watchdog по PID окна): закрыли или убили окно — на ПК
не остаётся ничего, видеопамять свободна. Служб, автозапуска и задач планировщика нет.
Код анализа — `ps-worker\app` (git clone этого репозитория по ssh, ветка из `config.json`), модели — из Windows-копии photosorter (только чтение).
`config.json`: `url` (http://192.168.1.10:8503), `token` (= `data/queue_token`), `branch`, `batch`, `threads`, пороги автостопа.
Иконка рисуется `make_icon.py` → `worker.ico`.
Управление без окна (для консоли и агентов): `ps-worker.bat start|stop|status|log [-n N]` в папке воркера. Канал — 127.0.0.1:8599
(`control_port`), токен из `config.json`; CLI только нажимает кнопки окна и читает статус, `start` открывает окно, если оно закрыто.
Второй экземпляр окна не запускается («Воркер уже запущен»).
