# Mediasorter: как устроено

Локальная сортировка домашнего фото/видео-архива: находит все лица и группирует их по людям без эталонных фото,
раскладывает кадры по сюжетам, ищет по тексту, собирает стопки похожих и копии, помогает чистить архив
(удаление обратимо). Всё работает локально, без облака. Из архива программа только **читает**; файлы меняются
только по действиям пользователя (удаление в карантин, подборки).

Одна программа на Go делает всё: веб-интерфейс (Vue, встроен в бинарник), JSON API и анализ (нейросети через
ONNX Runtime, видео через ffmpeg). Есть два способа запуска:

- **`mediasorter-desktop`** — программа для Windows / macOS / Linux: окно ([Wails](https://wails.io/)) с тем же
  интерфейсом; анализ на этом компьютере или подключение к серверу.
- **`mediasorter-web`** — сервер (Docker на NAS или домашнем компьютере), интерфейс в браузере.

## Из чего состоит (`web/`)

| Пакет | Что делает |
|---|---|
| `cmd/mediasorter-web` | сервер: переменные окружения, расписание сканирования, команды (см. ниже) |
| `cmd/mediasorter-desktop` | программа: окно, локальный сервер на 127.0.0.1, страница «Подключение», загрузка нейросетей |
| `internal/vision` | ONNX Runtime: SCRFD (лица) + ArcFace (векторы лиц), SigLIP2 (картинки и текст) + BPE-токенизатор Gemma; операции с картинками как в OpenCV (INTER_AREA / CUBIC, warpAffine); `ljpeg` — JPEG-кодировщик, дающий те же байты, что libjpeg |
| `internal/media` | чтение файлов: JPEG (цвет как у libjpeg), HEIC, встроенные превью RAW, PNG/WebP/GIF/BMP/TIFF; EXIF; кадры видео через ffmpeg |
| `internal/scan` | сканирование, люди (кластеризация), сюжеты, стопки и копии, качество, места по GPS |
| `internal/engine` | одна долгая задача за раз (сканирование, пересчёт людей, стопки…), прогресс для интерфейса, ленивая загрузка текстовой модели |
| `internal/api`, `internal/core` | JSON API интерфейса; удаление и Ctrl+Z, подборки, правка людей |
| `internal/db` | SQLite (без cgo), схема и миграции старых баз |
| `internal/setup` | загрузка моделей и ffmpeg при первом запуске программы (докачка после обрыва) |
| `frontend/` | Vue 3 + shadcn-vue + Tailwind 4 |

Модели (`models/`, ~1.7 ГБ, в git не кладутся):

| Файл | Откуда | Зачем |
|---|---|---|
| `det_10g.onnx`, `w600k_r50.onnx` | `buffalo_l.zip` из релиза InsightFace v0.7 | детектор лиц SCRFD + распознавание ArcFace (веса — только некоммерческое использование) |
| `siglip2/**` | huggingface.co/immich-app/ViT-B-16-SigLIP2__webli | сюжеты и поиск по тексту (понимает русский) |

## Конвейер

1. **Сканирование** (только новые и изменённые файлы; файлы с ошибкой пробуются снова; пропавшие из папки
   забываются; отсутствующая папка — например, не подключённый NAS — пропускается, а не «очищается»):
   декодирование → детектор SCRFD в двух масштабах (960 и 480 px: второй нужен для лиц на весь кадр — селфи) →
   выравнивание по 5 точкам (LMEDS, как `cv2.estimateAffinePartial2D`) → вектор ArcFace 512 → миниатюра лица.
   Плюс EXIF (дата с часовым поясом, GPS, камера), метаданные видео, dHash, превью 320 px (1 на фото, до 6 на
   видео; JPEG 75) и сразу вектор SigLIP2 каждого превью. Видео: ключевой кадр раз в 2 с (длинные — переходом
   к нужному месту, чтобы не читать весь файл с NAS), лица меньше 40 px пропускаются, одинаковые лица одного
   видео не повторяются. Места съёмки — ближайший город из таблицы GeoNames (офлайн).
2. **Люди** — только качественные лица (≥40 px, уверенность ≥0.65) → kNN-граф (косинус, 30 соседей) →
   Chinese Whispers → слияние кластеров с близкими центроидами → остальные лица прикрепляются к ближайшему
   человеку → «люди» из одного файла отбрасываются. Номера и имена сохраняются между пересчётами (по большинству
   прежних привязок и по центроидам подписанных людей); лица, отмеченные вручную, не трогаются.
3. **Сюжеты** — softmax по описаниям категорий (`scan/scenes.go`); у файлов без лиц «людские» категории
   исключены, «Прочее» — запасная.
4. **Стопки и копии** (`scan/stacks.go`): похожесть — SigLIP2, время — подсказка: чем больше пауза, тем выше
   нужная похожесть (до 2 с — 0.85 … до 2 ч — 0.95). Кадр входит в стопку, только если похож и на её первый
   кадр (длинная серия делится на моменты). Копия — SigLIP2 ≥ 0.985 и dHash ≤ 4, или dHash ≤ 2 при тех же
   пропорциях; **не** копия, если у обоих дата из EXIF и она отличается на ≥ 1 с, или одинаковые разрешение и
   формат, но разный размер файла. Скриншоты, документы и чеки — только как точные копии.
5. **Качество в стопках** — по оригиналу: резкость самых резких мест (размытый фон не штрафуется), резкость лиц,
   пере/недоэкспозиция, «красота» по SigLIP2. Внутри стопки признаки сравниваются между собой: лучший — 100.

Сервер делает 1–5 каждую ночь (`MS_SCAN_HOUR`, по умолчанию 3:00) и сразу после запуска, если давно не делал или
сменилась папка; программа — при запуске (если прошло больше 12 часов) и по кнопке «Обновить архив».

Видеокарта: Windows — DirectML (любая), Mac — CoreML, Linux/Docker — CUDA (образ `docker-compose.gpu.yml`).
Если драйвер не справляется с какой-то моделью, она сама переходит на процессор. Для DirectML у моделей лиц
делаются копии с фиксированным размером входа (со свободными размерами DirectML падает).

## База (SQLite)

- `files` — файл, тип, размеры, длительность, `n_faces` (0 = без людей), `taken_at` + `date_source`, GPS, `place`, камера, `phash`
- `faces` — лицо: файл, `person_id` (NULL = не сгруппировано), рамка, время в видео, вектор (float16), миниатюра,
  `manual` (1 = указано вручную)
- `persons` — человек: имя, скрыт ли, счётчики, центроид; `not_same` — пары «это разные люди»
- `previews` — JPEG-превью; `clip` — векторы SigLIP2 (float16); `tags` — топ-3 сюжета
- `stacks`, `copies`, `quality` — стопки, группы копий, оценки
- `collections`, `collection_files` — подборки; `deleted` — журнал удалений со снимком всех строк файла (JSON);
  `undo_log` — шаги Ctrl+Z; `settings` — папки для сканирования, место подборок, время последнего сканирования
- Представления: `file_people` (кто на каждом файле), `person_files`, `files_without_people`, `files_strangers_only`

Пример: все фото, где Петя ровно вдвоём с кем-то:

```sql
SELECT path, people FROM file_people WHERE people LIKE '%Петя%' AND n_people = 2;
```

## Удаление, подборки

- Удаление без подтверждения: файл уходит в карантин `_photosorter_deleted` (программа — внутри выбранной папки
  с фото, сервер — `data/_photosorter_deleted`), данные — в журнал `deleted`. **Ctrl+Z** возвращает (несколько
  шагов подряд). Окончательно освободить место — удалить карантин вручную. `protected.txt` — папки, из которых
  удалять нельзя.
- Подборки: «Перемещать» (файл уезжает из архива в папку подборки, данные едут с ним) или «Копировать» (жёсткая
  ссылка или копия). Один файл может быть в нескольких подборках. ZIP без сжатия; «Отправлено — удалить» убирает
  подборку и её файлы в карантин (Ctrl+Z возвращает).

## Сервер: настройки и команды

```
PS_DB=/data/faces.db          база
PS_SCAN_SRC="/photos /nas"    папки для сканирования (через пробел; в программе они хранятся в базе)
MS_MODELS=/app/models         модели          MS_ORT=/opt/ort/lib/libonnxruntime.so   ONNX Runtime
MS_FFMPEG=/opt/ffmpeg         папка с ffmpeg и ffprobe (иначе — рядом с программой или из PATH)
MS_WEB_ADDR=:8501             адрес интерфейса
MS_SCAN_HOUR=3                ночное сканирование; MS_SCAN=0 — не сканировать по расписанию
MS_SCAN_WORKERS=4             файлов одновременно;  MS_GPU=0 — только процессор
PS_PATH_MAP="//nas/home/=/mnt/nas-homes/user/"   пути старой базы с Windows → пути здесь
MS_PROTECTED=protected.txt
```

```
mediasorter-web              сервер (по умолчанию)
mediasorter-web nightly      сканирование и всё после него, сейчас
mediasorter-web cluster | tag | stacks | score   отдельные шаги
mediasorter-web models       скачать модели в MS_MODELS
```

## Сборка

- Сервер: `web/build.sh` (Node для интерфейса, Go с cgo для ONNX Runtime) или `docker compose build`.
- Программа: `desktop/build-windows.sh` (собирается на Linux через mingw-w64), `build-linux.sh` (WebKitGTK 4.1),
  `build-macos.sh` (на Mac). Выпуск для трёх систем — GitHub Actions `.github/workflows/desktop.yml` на тег `v*`.
  ONNX Runtime 1.24.4 едет вместе с программой (на Windows — сборка DirectML); нейросети и ffmpeg скачиваются
  при первом запуске в папку данных программы.

## Проверка

- `go test ./...` в `web/` — удаление/Ctrl+Z, подборки, люди (на временных базах).
- Совпадение с эталонным конвейером (`vision/parity_test.go`, `scan/parity_test.go`): эталонные результаты
  на ~100 реальных файлах (JPEG, HEIC, PNG, WebP, GIF, DNG, видео),
  `MS_PARITY=папка MS_MODELS=... MS_ORT=... go test -run Parity`. Проверено: токены 143/143, векторы лиц
  cos ≥ 0.989 без пропущенных лиц, превью байт в байт как у OpenCV, сюжеты 99.98 %, стопки и копии 100 %,
  люди 99.5 % без изменений.
- Кластеризацию проверяли на LFW (13 тыс. фото знаменитостей с подписями): полнота 98.9 % (лица человека в его
  главном кластере), чистота 99.76 %.
- Удалять что-либо в рабочем архиве при тестах нельзя — только на копиях.
